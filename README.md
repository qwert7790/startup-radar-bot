# Startup Radar

Бот публикует новые проекты из Product Hunt и Show HN в Telegram. Он переводит описание из источника на русский, добавляет категорию и ссылки на публикацию и сайт проекта, когда сайт указан. Длинные карточки отправляются текстом, чтобы сохранить подробности, которые не помещаются в подпись к фото.

## Откуда берутся подробности

- **Product Hunt.** Бот читает [ленту Atom](https://www.producthunt.com/feed). Для полноценного описания добавьте `PRODUCT_HUNT_TOKEN` из [настроек API](https://www.producthunt.com/v2/oauth/applications). Бот запрашивает название, краткое и полное описания и сайт именно этого запуска через официальный GraphQL API. Без токена бот работает по ленте, где описание часто состоит из одной строки. API требует токен, имеет лимиты и требует согласования коммерческого использования. Публичный вебхук новых запусков в официальной документации не найден. [Документация Product Hunt](https://api.producthunt.com/v2/docs)
- **Hacker News.** Бот читает текст Show HN и при коротком описании ищет дополнение среди первых восьми комментариев верхнего уровня от автора. Если источник прислал только заголовок и ссылку, бот так и сообщает в карточке. Функции, цены и аудиторию бот сам не придумывает. [Документация Hacker News API](https://github.com/HackerNews/API)
- Для стабильного перевода укажите `GOOGLE_TRANSLATE_API_KEY`. В Google Cloud Console включите Cloud Translation API, настройте биллинг, создайте API key и ограничьте его этим API. Сервис тарифицируется по объёму перевода. Без ключа бот использует общедоступный интерфейс Google Translate, который может ограничивать автоматические запросы. [Настройка Cloud Translation](https://cloud.google.com/translate/docs/setup) Если перевод недоступен или не содержит кириллицы, карточка остаётся в SQLite для повтора. Сервисы и авторы могут менять данные и уровень детализации.

## Как быстро выходят посты

| Режим | Hacker News | Product Hunt |
| --- | --- | --- |
| Постоянный процесс на VPS | Изменения списка новых публикаций будят бота через поток Firebase. Запасная проверка примерно каждые 15 секунд | Проверка Atom примерно каждые 60 секунд |
| GitHub Actions | По расписанию, номинально каждые 5 минут | По тому же расписанию |

Фактическое время зависит от того, когда запись появится в API или ленте, времени загрузки и перевода, очереди и ответа Telegram. Лента Product Hunt может отставать от сайта и охватывать только часть запусков. Поток Firebase сообщает об изменении списка, после чего бот загружает записи и отбирает Show HN. [Поток Firebase](https://firebase.google.com/docs/database/rest/retrieve-data#section-rest-streaming)

Пять минут — минимальный интервал расписания GitHub Actions. Запуски могут задерживаться или пропускаться, расписание действует в ветке по умолчанию. [Документация GitHub](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)

## Вариант 1. Обновить существующий GitHub Actions

1. Сохраните резервный ZIP и оставьте ветку `backup-working` для отката. В рабочей ветке замените `bot.py`, `requirements.txt`, `.github/workflows/main.yml`, инструкции и файлы настроек примера. **Оставьте свежую базу `data/startup_radar.sqlite3` из вашего репозитория**. В проекте из ZIP лежит её снимок на момент подготовки обновления.
2. Откройте **Settings → Secrets and variables → Actions**. Действующие секреты `TELEGRAM_BOT_TOKEN` и `TELEGRAM_CHANNEL_ID` уже подходят. Для полных описаний Product Hunt добавьте необязательный секрет `PRODUCT_HUNT_TOKEN`. Для перевода добавьте `GOOGLE_TRANSLATE_API_KEY`.
3. После обновления ветки `main` откройте **Actions → Startup Radar publisher → Run workflow**. Галочка **Send a test Telegram message** отправляет одно тестовое сообщение. Для проверки источников и публикаций запускайте без галочки. Сначала можно проверить на отдельном тестовом канале.
4. В журнале открывайте шаг **Collect projects or send test**. Если новых записей нет, итог с нулём публикаций нормален. История и очередь сохраняются отдельным шагом, в том числе при частичном сбое источника.

## Вариант 2. Постоянный запуск на VPS с Docker

1. Подготовьте Linux-сервер с Docker и Docker Compose. Чтобы протестировать запуск параллельно со старым ботом, используйте отдельный тестовый канал и отдельную папку с базой. Дайте боту право публиковать в выбранном канале.
2. Перед переключением рабочего канала в **Actions → Startup Radar publisher** отключите workflow и дождитесь окончания уже запущенного задания. Возьмите последнюю `data/startup_radar.sqlite3` из `main` и поместите её в папку `data` распакованного обновления. Так сохранятся опубликованные ID и очередь. Запускайте только один экземпляр на рабочий канал.
3. В папке проекта выполните:

   ```bash
   cp .env.example .env
   chmod 600 .env
   nano .env
   ```

   Заполните `TELEGRAM_BOT_TOKEN` токеном из BotFather, `TELEGRAM_CHANNEL_ID` адресом канала (например, `@my_startup_channel`) и при наличии `PRODUCT_HUNT_TOKEN`. Для перевода добавьте `GOOGLE_TRANSLATE_API_KEY`. Файл `.env` храните на сервере и не отправляйте в GitHub. Сохранить в nano можно через Ctrl+O, Enter, выйти через Ctrl+X.
4. Запустите бота и откройте журнал:

   ```bash
   docker compose up -d --build
   docker compose logs -f --tail=100
   ```

   Ctrl+C закрывает просмотр журнала. Контейнер продолжает работать. Для остановки используйте `docker compose down`. Папка `data` сохраняется между перезапусками.
5. Для возврата на Actions остановите контейнер, перенесите его свежую базу в рабочую ветку и включите workflow. Используйте текущую историю даже при откате кода. Старый снимок базы может привести к повторным публикациям.

Без Docker можно создать окружение Python 3.11+, установить `pip install -r requirements.txt` и запустить `python bot.py` с тем же `.env`. Для однократного запуска используйте `python run_once.py`. На совершенно пустой базе бот по умолчанию запоминает текущие записи и ждёт новых.

SQLite обновляется после подтверждения отправки Telegram. При сбое между отправкой и записью истории либо после неопределённого ответа Telegram возможен повтор.
